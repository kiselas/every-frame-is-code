# Промптинг: как ставить задачу

## Два режима промпта

**Короткий, про тему.** Когда стиль не важен или хочется, чтобы модель удивила. Тема, аудитория, длина, формат, обязательные слова. Шот-лист не нужен, его планирует модель. По наблюдениям комьюнити, именно тема и слова промпта сильнее всего определяют вид, а стилевые пресеты и референсы стягивают всё к одному виду.

```
Как работает шумоподавление в наушниках? Вертикальный эксплейнер для TikTok, ~20 с.
```

**Точный, про устройство.** Когда нужна конкретная механика: игра, пиксель-арт, симуляция, физика, строгая сетка. Здесь конкретика работает: разрешение, палитра, состояния персонажа, правила физики, управление.

```
Самодостаточный HTML, 128x96, фиксированная палитра из 24 цветов, масштаб x6 с image-rendering: pixelated.
Персонаж-маг со стейт-машиной: idle → charge → cast → recover.
Частицы заклинания привязаны к пиксельной сетке и меняют цвет по палитре к концу жизни.
При касте тряска экрана на целые пиксели.
```

## Что всегда полезно указать

- **Вопрос или история.** Что зритель поймёт или почувствует к концу.
- **Для кого.** «Для двухлетки» и «для финтех-блога» дают совершенно разный темп и рисунок.
- **Длина и площадка.** Площадка сразу задаёт формат (9:16, 16:9, 1:1).
- **Точный текст**, если он должен появиться: название, слоган, финальная фраза.
- **Стиль словами**, если он важен: «в духе научного учебника 1950-х», «гравюра», «советский диафильм», «швейцарский плакат», «чертёж на кальке». Не мудборд.
- **Чего избегать**, конкретно. Общее «не делай как ИИ» меняет один дефолт на другой. Работают названные паттерны: «без неоновых градиентов, без центрированного текста, без тёмно-синего с янтарным».

## Шаблоны

### Эксплейнер
```
[Вопрос]? Анимационный эксплейнер [длина], [формат], для [аудитория].
Стиль: [описание словами или «выбери стиль из самой темы и объясни выбор»].
Обязательный финальный титр: «...».
Один непрерывный мир, камера движется через него. Музыка кодом на Web Audio, склейки на бит.
Сначала покажи план: бит-сетку, список шотов, события. Потом код.
```

### Кинематографичный ролик под озвучку
```
Ролик [длина], 16:9, под готовую озвучку. Текст и таймкоды фраз ниже.
Визуальный мотив: [один главный образ, например огонь / свет / вода / сеть].
Титры: ключевые фразы крупной типографикой, появляются по фразам озвучки.
Каждая фраза озвучки получает свой визуальный бит. Переходы мотивированы движением
(объект уводит камеру в следующую сцену), а не кроссфейдами.
Таймкоды:
0.00–4.20 «...»
4.20–9.80 «...»
```

### Кинетическая типографика
```
Кинетическая типографика на [текст/стих/цитата], [длина], [формат].
Шрифт: [название из Google Fonts] или выбери под тон.
Каждое слово появляется со своей механикой в зависимости от смысла
(тяжёлое падает, быстрое пролетает, тихое проявляется). Ритм по [BPM].
```

### Игра
```
Браузерная игра в одном HTML: [жанр], [сеттинг].
Core loop: [что игрок делает снова и снова].
Управление: [клавиши]. Ощущение от управления: [отзывчиво / тяжело / скользко].
Juice: хитстоп при ударе, тряска камеры по «травме», частицы, squash & stretch, звук на каждое действие.
Один уровень, но отполированный. Меню паузы и рестарта.
Физику пиши сам, без библиотек.
```

### 3D-сцена
```
Three.js (ES-модули через importmap с jsdelivr), один HTML.
Сцена: [описание]. Настроение: [время суток, погода, эмоция].
Свет: один ключевой источник [откуда], заполнение, контровой.
Постобработка: bloom, лёгкий vignette, зерно. Тональная компрессия ACES.
Камера: [пролёт / облёт / статичная с дыханием], движение на easing.
```

### Воссоздание по референсу
```
Воссоздай этот кадр полностью процедурно (без использования картинки) как анимированную сцену.
Сохрани композицию, палитру и свет. Добавь живое движение: [что должно двигаться].
```

## Фразы для итераций

Правки по конкретным кадрам работают лучше общих:
- «На 0:14 титр лежит на персонаже. Сдвинь в нижнюю треть.»
- «С 0:22 по 0:27 ничего не происходит. Добавь медленный наезд и дрейф частиц.»
- «Свечение плоское. Сделай ядро ярче и добавь широкий слабый ореол вторым слоем.»
- «Второй акт затянут. Сократи до 12 с, склейки на каждые 2 такта вместо 4.»
- «Меньше оранжевого. Акцент оставь только на ключевом слове.»
- «Контуры толстые и скруглённые, выглядит по-детски. Тоньше, с лёгкой дрожью линии.»

## Советы по работе

- Проси сначала план, потом код. План проверять дешевле.
- Не проси «подумай шаг за шагом»: современные модели (Claude Opus, GPT) рассуждают сами, такие фразы только замедляют.
- Отдавай всю задачу сразу, а не серией команд.
- Если ролик длинный (больше 60–90 с), собирай его частями в одном проекте с общим стилем и таймлайном.
