# Рендер и проверка

## Рендер в MP4

Скрипты в папке `render/`. Требования: Node 18+, Chrome, ffmpeg.

```bash
cd render && npm install
node render.mjs ../my-film.html ../out.mp4
```

Страница должна выставлять `window.__meta = { W, H, FPS, DURATION }`, `window.__draw(t)` и `window.__ready = true` после загрузки шрифтов (см. 01-pipeline.md). Если есть `window.__renderAudio`, звук будет сведён автоматически.

## Контакт-лист

Один кадр каждые полсекунды на одном изображении. Главный инструмент проверки: видно темп, мёртвые участки, композицию и повторы.

```bash
./render/contact-sheet.sh out.mp4 sheet.png        # по умолчанию 2 кадра в секунду, 8 колонок
```

Агенту: после каждого рендера открой контакт-лист и опиши, что видишь, прежде чем править.

## Чек-лист

**Композиция и текст**
- [ ] Текст не перекрывает объекты и не лежит на самом ярком месте
- [ ] Текст в безопасных зонах, не обрезан краями
- [ ] Каждый титр держится достаточно для чтения
- [ ] В каждом кадре понятно, куда смотреть

**Движение и темп**
- [ ] Нет участков без движения дольше 2 с
- [ ] Нет линейных движений там, где нужна кривая
- [ ] Шоты сокращаются к пику, есть пауза перед пиком
- [ ] Первые 2 секунды цепляют (для вертикальных площадок)

**Визуал**
- [ ] Объекты не выходят за края там, где не должны
- [ ] Нет резких скачков яркости между кадрами (кроме намеренных вспышек)
- [ ] Палитра выдержана, акцент не размазан по всему кадру
- [ ] Нет мерцания от `Math.random()` в отрисовке

**Звук**
- [ ] Склейки на бит
- [ ] Нет одиночных громких ударов после тишины
- [ ] Голос разборчив поверх музыки
- [ ] Итоговая громкость около −14 LUFS

**Техника**
- [ ] Шрифты загружены до первого кадра
- [ ] Два рендера дают одинаковый результат
- [ ] Живой режим и рендер совпадают по таймингу

## Частые проблемы первого черновика

- Персонажи с толстым скруглённым контуром выглядят по-детски.
- Текст нарисован поверх объектов.
- Длинные участки, где ничего не происходит.
- Всё одновременно: нет stagger, нет иерархии движения.
- Переходы только кроссфейдом.
- Один и тот же тип кадра (крупность, композиция) всю дорогу.
- Громкие одиночные удары в музыке.

## Форматы экспорта

| Площадка | Размер | FPS |
|---|---|---|
| YouTube, сайт | 1920×1080 | 30 или 60 |
| Reels, Shorts, TikTok | 1080×1920 | 30 или 60 |
| Telegram, соцсети квадрат | 1080×1080 | 30 |

Кодирование: H.264, `-pix_fmt yuv420p`, `-crf 18`, `-movflags +faststart`. Для GIF-превью: `ffmpeg -i out.mp4 -vf "fps=15,scale=640:-1:flags=lanczos,split[a][b];[a]palettegen[p];[b][p]paletteuse" preview.gif`.

## Производительность живого режима

Рендер покадровый, поэтому тяжёлый кадр не портит MP4. Но живой просмотр должен идти хотя бы на 30 fps, иначе сложно оценивать. Если тормозит: уменьши число частиц в живом режиме, кешируй статичные слои в буферы, размывай уменьшенные копии, переходи на WebGL.
